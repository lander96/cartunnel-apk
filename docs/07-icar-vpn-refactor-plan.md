# iCAR VPN 兼容性与单模式重构计划

状态：待用户确认后实施

基线：main / 68e8958cb55f0d1e3c50c1a146dd498df9d9f43b

目标设备：iCAR 03 为主，Android 9 / 11；普通 Android 真机作为回归设备

参考样本：畅流-v7.1-7169-极速版-64位推荐.apk

本文档冻结下一轮的产品行为、兼容策略和验收边界。参考 APK 只用于互操作与行为对比，禁止复制其私有代码、资源、证书、服务地址或二进制产物。

## 1. 结论

首轮不降低 targetSdk，也不照搬参考 APK 的高风险权限。现有车机失败最可能不是默认路由缺失，而是以下两个启动条件在车机网络环境中产生了误判：

1. 当前 AndroidTunnelRuntime 在创建 TUN 之前，强制访问 Cloudflare 测试地址；测试失败即把有效节点判定为不可用并终止启动。
2. 当前 ConnectivityMonitor 依赖 activeNetwork/default network。部分车机固件即使套接字可用，也可能返回空、延迟或厂商自定义网络，进而被应用解释为“网络不可用”并反复重连。

参考 APK 的默认 IPv4 路由与本项目现有 Ipv4RoutePlanner 基本同义。有效修复应先解除错误的启动门禁，并采用参考 APK 已验证过的 TUN/DNS/IPv4 参数；不能只新增权限或盲目降低 SDK。

参考 APK 还声明了安装包、悬浮窗、忽略电池优化、查询全部应用、旧存储等权限。本项目不需要这些能力，本轮不得增加。

## 3. 产品范围

### 3.1 保留

- VLESS + REALITY + XTLS Vision 节点。
- Android 全局 VPN。
- 可选“绕过局域网”。
- 节点新增、编辑、删除、选择、导入、导出与测速。
- VPN 授权、前台通知、开机连接、网络变化重连、休眠/唤醒恢复。
- 脱敏诊断日志、版本与许可证查看。

### 3.2 删除

- 首页 VPN / 本地代理模式切换。
- 用户可用的本地 SOCKS/HTTP 代理说明。
- Xray HTTP 10809 inbound。
- TunnelMode.LOCAL_PROXY 及所有可达分支。

127.0.0.1:10808 SOCKS 必须作为 Xray 与 HEV 之间的内部实现保留，但不得在 UI 中宣传为用户功能，也不得监听非 loopback 地址。

### 3.3 不做

- 不复制参考 APK 的远程平台、账号、订阅、升级或 ADB 功能。
- 不新增 root、悬浮窗、通知监听、安装包、无障碍、查询全部应用权限。
- 不做按应用分流、IPv6 VPN 或多协议。
- 不以降低 targetSdk 作为首轮修复。

## 4. 兼容性设计

### 4.1 启动链路

冻结顺序：

1. 校验 VPN 授权与选中节点。
2. 初始化并启动 Xray，仅等待 127.0.0.1:10808 监听就绪。
3. 创建 IPv4 TUN。
4. 启动 HEV，将 TUN 转发到内部 SOCKS。
5. 资源全部就绪后发布 Connected。
6. 连接后异步刷新节点延迟；测速失败只更新健康状态，不得断开 VPN。

禁止在第 1～5 步之间访问任何公共网站作为成功门槛。SOCKS 监听就绪是本地核心 readiness，不代表公网健康，但可以避免公共测试站点故障阻止车机建隧道。

清理顺序继续保持 HEV → ParcelFileDescriptor → Xray。用户停止必须取消启动、测速和重试。

### 4.2 TUN 与路由

- session：CarTunnel。
- MTU：1500。
- IPv4：10.10.0.2/32。
- DNS：223.5.5.5、119.29.29.29。
- 全局模式：0.0.0.0/0。
- 绕过局域网：沿用 Ipv4RoutePlanner 生成的公开 IPv4 网段。
- 排除应用自身，防止 Xray 出站再次进入 TUN。
- 显式 allowFamily(AF_INET)；本版不向 TUN 添加 IPv6 地址或 IPv6 默认路由。

HEV 的 tunnel.ipv4 必须与 10.10.0.2 一致，并增加 TCP 300000ms、UDP 60000ms 的读写超时。

### 4.3 网络可用性与重连

ConnectivityManager 只能提供“底层网络可能变化”的提示，不能直接证明公网不可用：

- 启动时即使 activeNetwork 为空，也允许进入 Xray/TUN 启动链路。
- 监听带 INTERNET 且非 VPN 的网络集合，不读取 VPN 自身作为底层网络。
- onAvailable / capabilities 变化合并并等待 2 秒稳定后，只在物理网络身份确实变化时触发一次重建。
- onLost 不立即发布“网络不可用”；先等待宽限期并检查是否存在其他非 VPN 网络。
- OEM 无法可靠报告底层网络时，保持现有会话并交给数据面失败/用户操作处理，避免重连风暴。
- 所有网络事件仍通过 TunnelSessionCoordinator 串行化，禁止 callback 直接操作 Xray、HEV 或 TUN。

日志区分 NETWORK_HINT_CHANGED、NETWORK_HINT_EMPTY、CORE_READY、TUN_READY、HEV_READY、HEALTH_CHECK_FAILED；不得记录 UUID、Reality key、完整域名或 URI。

### 4.4 节点健康检查

- 手工“测试”与连接后异步测速使用相同探测器。
- 首选 https://www.baidu.com/；失败后可再试 https://www.qq.com/，任一成功即为可用。
- 两个地址都失败只能说明“当前网络下测试失败”，不能自动删除节点，也不能在已连接状态下强制停 VPN。
- 持久化最近一次结果：状态、延迟、时间和安全错误码。不得持久化原始异常或响应内容。
- 节点配置被编辑后立即将旧测试结果标记为过期/未测试；节点删除时同步删除健康记录。

### 4.5 车机启动与唤醒

设置中提供：

- 开机自动连接，默认关闭。
- 连接失败自动重试，默认开启。
- 网络切换后重连，默认开启。
- 休眠/唤醒后恢复，默认开启。
- 绕过局域网，默认关闭。

标准接收动作：BOOT_COMPLETED、MY_PACKAGE_REPLACED、USER_UNLOCKED。兼容动作只先加入 iCAR/高通或 AutoChips 实测所需的 QUICKBOOT_POWERON 与 autochips.intent.action.QB_POWERON。

- 真正的开机/快速上电事件以 autoConnect 为准：开关开启且存在有效节点时，将 desiredRunning 置为 true 后连接；不要求关机前仍处于连接状态。
- MY_PACKAGE_REPLACED 和普通唤醒事件只恢复已有 desiredRunning 意图，避免应用更新或伪造广播意外启动 VPN。
- 厂商广播必须经过动作分类、有效节点校验和冷却期，不能从 Intent 读取节点或凭据。

如实现启动/恢复期间的短时 WakeLock，只允许最长 30 秒并在成功、失败、取消和异常路径全部释放。不得请求永久忽略电池优化。

### 4.6 targetSdk 兼容降级条件

首轮保持 targetSdk 36。参考 APK 使用 targetSdk 28 只是观察事实，尚无证据表明它是 iCAR 失败原因。

只有完成上述修复后，iCAR 仍在系统层拒绝 establish、前台服务或后台启动，并取得 logcat / dumpsys 证据时，才建立单独 carCompat 构建变体评估 targetSdk 28。该变体不得替代主构建，也必须由用户再次确认后实施。

## 5. UI 设计

首页改成单层结构：

1. 顶部状态区：未连接、连接中、已连接、重连中、错误；显示当前节点名和连接时长。
2. 主操作：一个明显的“连接 / 断开”按钮，只控制全局 VPN。
3. 节点列表：直接展示全部节点，不再先打开多层对话框。
4. 列表工具：新增、粘贴导入、文件导入；批量导出放入更多菜单。
5. 设置入口：打开独立设置页。

每个节点行显示：

- 选中标记、节点名称、服务器的安全摘要。
- 最近状态：未测试、测试中、可用 N ms、测试失败、结果已过期。
- 最近测试时间。
- 单独“测试”按钮和编辑/删除/导出菜单。

点击节点行只切换当前节点；VPN 运行中禁止切换、编辑、删除或批量导入，并给出明确提示。测速可在 VPN 停止时对任意节点执行；运行中只展示当前会话的异步健康结果，不启动第二个 Xray 实例。

布局继续使用 XML/View，适配 1280×720 横屏，并保证普通手机竖屏可滚动。不引入 Compose。

## 6. 数据迁移

设置结构移除 lastMode，新增 autoReconnect、reconnectOnNetworkChange、reconnectOnWake。

升级时如果旧设置 lastMode=LOCAL_PROXY：

- 不自动把它转换成正在运行的全局 VPN，以免升级后意外接管全部流量。
- 将 desiredRunning 设为 false、删除旧 mode 字段，要求用户手工点击连接。

旧 VPN 模式可保留 desiredRunning 和开机连接意图。迁移必须幂等并有单元测试。

### M1：兼容性修复

- 移除启动前公共网络探测门禁。

- 重写底层网络提示逻辑。

- 删除 LOCAL_PROXY 的 UI、状态、命令、配置分支和 HTTP inbound。
- 完成旧设置迁移，保持现有状态机竞态测试通过。

- 引入列表适配器与节点健康仓库。

### M4：设置与车机恢复

- 独立设置页。
- 按开关应用开机、网络变化和唤醒策略。
- 加入最小厂商广播、冷却和重复事件抑制。

- JVM、lint、instrumentation 编译与执行、debug/release 构建。
- 普通 Android 真机回归。
- iCAR 03 真实启动、VPN、休眠/唤醒、网络切换与重启验收。

## 8. 验收标准

代码 Gate：

- 既有状态机、stop token、epoch 和清理顺序测试不得回退。
- 新增测试证明外网测速失败不阻止 VPN 启动。
- 新增测试证明 activeNetwork 为空不发布终止性“无网络可用”。
- 新增 TUN 配置契约、设置迁移、健康状态持久化/失效、重连开关测试。
- testDebugUnitTest、lintDebug、assembleDebugAndroidTest、assembleDebug、assembleRelease 全部通过。
- instrumentation 必须在模拟器或真机实际执行，不能只报告“编译通过”。

功能 Gate：

- 首页不存在本地代理入口，APK 不监听 HTTP 10809。
- 节点列表直接可见，最近测试状态和时间在进程重启后仍存在。
- 用户点击连接后，Cloudflare、百度或腾讯测试站点不可达都不能单独阻止 TUN 建立。
- 全局 VPN 下 IPv4 HTTP、HTTPS、DNS、UDP 可用；应用自身无路由回环。
- 用户停止后在本次开机周期不再自动重连；下次真实开机是否连接由“开机自动连接”开关决定。关闭相应设置后，网络切换或普通唤醒不会重建。
- 普通 Android 真机和 iCAR 03 均完成至少 20 次连接/断开循环，无崩溃、无残留 VPN 图标。

交付 Gate：

- 生成新的可侧载 debug APK、SHA-256、版本说明和完整构建日志。
- 明确区分 debug 候选包与正式签名 release。
- iCAR 未实测前只能称“iCAR 兼容候选包”，不能称正式可交付版本。

## 9. 风险与回退

- 10.10.0.2/32 与 198.18.0.1/30 都是虚拟接口内部地址。首轮采用参考包参数；若特定系统拒绝 /32，通过一次设备日志决定是否回退，不并行保留隐式分支。
- 国内测速站点仍可能被网络策略阻断，因此测速永远不是启动门禁。
- 厂商广播可能重复或可被伪造，必须校验本地运行意图、有效节点和冷却时间。
- 若新网络监听在某固件上没有回调，现有 VPN 应继续运行；这优于把不确定事件解释为断网。
